## Progress

**Реализовано:**
- Modbus TCP (pymodbus 3.6.x): 01–06, 15/16; запуск/остановка сервера через API; при ошибке «порт занят» — понятный ответ в API.
- API: `/health`, `/api/config`, `/api/state/{kind}` (GET/PUT), `/api/state/{kind}/batch`, `/api/server/status`, `/api/server/start`, `/api/server/stop`, `/api/profiles` (GET/POST), `/api/profiles/{slug}/load`, `/api/profiles/{slug}/update`, DELETE профиля; **`/api/generators`** (GET/PUT) — список и сохранение конфигурации генераторов.
- Хранилище: `config.yaml`, `state.json`, каталог `profiles/` (YAML с полями config, state, **generators**); профиль `default` создаётся автоматически и защищён от удаления.
- **Генератор сигналов (backend):** модуль `signal_generators` (SignalGeneratorEngine, фоновый поток), `encoding_utils` (кодирование INT16/FLOAT32/FLOAT64 в регистры), интеграция в lifespan; генераторы сохраняются и загружаются вместе с профилем. Движок хранит все генераторы (включённые и выключенные), а run‑loop учитывает флаг `enabled`, что позволяет корректно round‑trip'ить конфигурации через профили и API генераторов.
- **Modbus‑лог (backend):** `modbus_log` хранит события Modbus; при FC05/06/15/16 в `modbus_server.InMemoryDataStore.setValues` добавляются записи типа `modbus_write` с полями `kind` (`coils`/`holding`), `start`, `count` для точной привязки изменений к диапазонам регистров.
- GUI:
  - Конфигурация, регистры (одиночная и batch‑запись, пресеты), Modbus‑сервер (статус, Запустить/Остановить), профили; при включённой авторизации — форма входа.
  - Тёмный dashboard‑стиль, таблица регистров по образцу классических симуляторов, битовый вид для coils, форматы INT16/32/64, FLOAT32/64, BITMAP для holding/input, редактирование holding во всех форматах.
  - **Блок «Генератор сигналов»** под таблицей регистров: добавление/редактирование/удаление генераторов, выбор типа сигнала, формата, адреса, параметров и цвета подсветки (по умолчанию синий; поле цвета в стиле приложения); таблица с колонкой «График» (живые данные), «Значение», неоновая подсветка. Числовые поля формы — проверка по потере фокуса, при невалидном вводе подстановка значения по умолчанию (как у регистров).
  - **Автообновление** значений регистров в таблице (~1.5 с); опрос значений генераторов ~120 мс для живого графика и отображения значения.
  - **Подсветка ячеек таблицы регистров:**
    - holding‑ячейки, в которые пишет включённый генератор, подсвечиваются постоянным неоном выбранного цвета.
    - при Modbus‑записи (событие `modbus_write` в логе) на соответствующие ячейки holding и `coils` накладывается зелёная вспышка (CSS‑анимация), которая мгновенно загорается и медленно затухает; для holding вспышка не перекрывает диапазоны генераторов.
  - Журнал событий: фильтры по типу/IP, поиск, экспорт в JSON; отдельные фильтры «Генераторы» и «Профили», цвета для событий `generator_*` и `profile_*`. Фильтры (кроме «Все») можно включать/выключать по отдельности и комбинировать. При действиях над генераторами и профилями пишутся подробные события (создание/изменение/удаление/вкл/выкл генераторов, сохранение/обновление/загрузка профиля, загрузка генераторов из профиля с их полными параметрами).
  - **Сворачиваемые панели:** кнопки‑стрелки в правом верхнем углу панелей «Настройки» (объединяет Modbus‑сервер, конфигурацию и профили), «Регистры», «Генератор сигналов» и «Журнал событий». При сворачивании остается только заголовок панели; содержимое (формы, таблицы, тулбары) скрывается. Внутри «Настройки» панели сервера, конфигурации и профилей расположены в одну строку и адаптируются по ширине.
- Авторизация: опциональная Basic Auth по env.
- Тесты: health, state, batch, server, profiles, **generators API**, round‑trip генераторов через профили; `pytest` с временным DATA_DIR.
- README: запуск, порты, профили, пресеты, **генератор сигналов**, тесты.
